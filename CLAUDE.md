## 1. What this is

A submission to the **DEV Weekend Challenge: Dog Days Edition**, competing for **Best Use of ElevenLabs**.

**Hard deadline: 2026-08-17 06:59 UTC.** Built, deployed, recorded, and written by then. No extension.

**Product.** Eight real shelter dogs. Each listing is read twice — once by a flat institutional voice, once by a voice *generated from that dog's own shelter record* via ElevenLabs Voice Design. One hero dog goes further: a slider scrubs through its stay, and the voice degrades as the days accumulate.

Two axes, one mechanism:
- **Across dogs** — different records produce different voices
- **Within one dog** — the same record over time produces a voice that gets tired

**Thesis.** Adoption is an emotional decision made from a bureaucratic artifact. Voice Design converts structured shelter data into an emotional signal. Waiting has a sound.

`intake_type: "unknown"` is the common case — most shelters do not publish why an animal arrived. It is a real value, not missing data, and it contributes no modifier.

## 6. The three things that decide whether we win

### 6.1 Timestamp-preserving audio swap

**Build first. Verify by ear before anything else.** Hearing the same sentence flip voices mid-word is the moment a judge remembers.

```js
function swapSource(newSrc) {
  const t = audio.currentTime;
  const wasPlaying = !audio.paused;
  audio.src = newSrc;
  audio.addEventListener('loadedmetadata', () => {
    audio.currentTime = t;
    if (wasPlaying) audio.play();
  }, { once: true });
}
```

**One shared `<audio>` element** for the whole page. State: `currentDogId`, `mode`, `heroDay`. Switching dogs stops playback.

The hero slider uses this same function — dragging swaps sources while preserving position, so the voice ages mid-sentence.

### 6.2 The attribute → prompt function

The intellectual core. **Real documented code** in `src/voicePrompt.js`, not a hardcoded lookup. The post shows this function.

```
BASE       age_band  puppy→"bright, very fast, unsteady, tumbling"
                     young→"quick, energetic, eager"
                     adult→"even, steady, measured"
                     senior→"low, slow, weary, patient"
PITCH      size      large→"lower, resonant"   small→"higher, clipped"
WEARINESS  days      1-29→(none)  30-119→"a little flat"
                     120-179→"quiet and tired"  180+→"flat, barely lifting, worn through"
GUARD      returns   1→"slightly hesitant"  2+→"anxious, over-eager, trying too hard"
STRAIN     intake    stray→"watchful"  owner_surrender→"resigned"  returned→"uncertain"
```

Signature: `buildVoicePrompt(attributes) → string`. Pure function, no side effects. Concatenate fired modifiers. Surface the derivation in the UI — showing the work is what scored for the previous Google AI winner.

### 6.3 The hero slider

**It is a demonstration of the mapping function, not a claim about a real dog's stay.** No shelter publishes intake dates, so no dog's actual timeline is knowable — the post states this outright. The slider holds one real record fixed and moves `days_in_shelter` alone, showing what the function does with that one variable. Label it as such in the UI; never imply the hero waited these lengths.

Four discrete stops, not continuous, labelled by elapsed time rather than raw day number:

| Stop | `days_in_shelter` | Weariness band |
|---|---|---|
| Week 1 | 3 | (none) |
| Month 1 | 30 | a little flat |
| Month 4 | 120 | quiet and tired |
| Year 2 | 730 | flat, barely lifting, worn through |

Each stop lands in a **different** weariness band, so every drag is audible and every band the function can reach is demonstrated. Two tests enforce this — if the stops or bands change such that two stops collide, they fail. Stops live in `SLIDER_STOPS` in `src/voicePrompt.js`.

As the slider moves right the card should visibly cool — this is the one place motion earns its keep.

## 7. Visual direction

**Subject world:** municipal animal-control paperwork meets broadcast radio. Kennel cards, stamped dates, cage numbers — against VU meters and an on-air light.

The card **is** an institutional document in flat mode and **becomes** something warm in voice mode. The visual transition carries the same argument as the audio. That is the signature element; spend all boldness there, keep everything else quiet.

```
--paper   #E8E4DA   manila kennel card
--ink     #1C1A17   stamped ink
--rule    #B8B0A0   form rules
--on-air  #D8442F   ONLY the live indicator
--warm    #F2C14E   voice-mode accent
```

No sixth colour.

**Type:** condensed grotesque for names (Archivo Condensed / Oswald); monospace for listing text and data (IBM Plex Mono) because kennel cards are typewritten. In voice mode the mono **relaxes** — lighter weight, looser tracking. Never swap font families.

**Mode strip** across each card top: flat mode shows cage number, intake date, `INTAKE RECORD` stamp, hairline rules, all grey. Voice mode lights the on-air dot, animates a waveform, warms the background.

**Quality floor:** responsive to 375px, visible keyboard focus, `prefers-reduced-motion` respected (waveform static), visible audio transport.

## 11. The DEV post (Writing Quality is ~20% of the score)

Not documentation. An argument.

1. **Open with a real listing quoted flat.** Ask what it tells you about the animal. No preamble.
2. **The sentence four dogs share.** Then quote it again — and reveal it is Ponyboy's listing, and Hart's, and two others', word for word. Ponyboy is a 3-year-old Anatolian Shepherd, 77 lb; Hart is a 9-year-old pit bull who has been waiting far longer. The shelter's template cannot tell them apart. **This is the headline finding, and it belongs above the thesis** — it proves the argument from the source material instead of asserting it. The page detects these overlaps at load (`src/sharedText.js`, exact match, no fuzzy matching), so the count is checkable, not claimed.
3. **The thesis** — one paragraph. The listing text is 100% the shelter's; the only thing we add is the voice. The cheerfulness is the institution's, the weariness is the record's.
3. **The hero dog.** Day 1 to day 214, same function, one variable moved. This is the emotional and technical centrepiece.
4. **The mapping table and the actual code.** Technical Execution evidence no other entry will have.
5. **Why Voice Design, not preset TTS.** Preset = picking from a menu. Generated = the record produces the voice. **Name the control honestly:** the flat reading is ElevenLabs' stock **"Roger"** — their own description is *"Charismatic, positive and conversational"* — on **Eleven Multilingual v2**, the same model as the designed voices. The control is not a monotone robot; it is the upbeat register shelter marketing is already written in, which makes the contrast one of **tone, not expressiveness**. That distinction is the honest version of the claim and pre-empts the obvious objection. (Free tier ended with 116 credits remaining.)
6. **Why pre-generated audio** — determinism, no key exposure, no rate limits. Engineering judgment.
7. **Limitations, plainly.** The voices are an interpretation, not the dog. The mapping is authored, not learned. Eight dogs is not a study. The degradation curve is a design choice, not a measurement. These dogs may already be adopted.

Section 7 is counterintuitive and high-leverage. Most submissions overclaim; the one that knows what it doesn't know reads as mature.

Embed the demo video near the top. A missing video sinks otherwise-good entries.
